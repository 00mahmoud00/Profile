How I structure a .NET solution

Dependencies point inward. The domain is plain C# with no database or framework in it, so the business rules can be tested on their own. These are the tools I use at each layer.

  1. Domain

    Entities, value objects and aggregates, modelled with Domain-Driven Design.

    • C#
    • Domain-Driven Design
    • OOP

  2. Application

    Use cases that coordinate the domain and declare the interfaces the outer layers implement.

    • .NET Core
    • Clean Architecture
    • SOLID
    • Design patterns

  3. Presentation

    Admin dashboards, interactive UIs and HTTP APIs.

    • Blazor (SSR & WASM)
    • MudBlazor
    • ASP.NET Core

  4. Infrastructure

    Persistence and the third-party services the use cases depend on.

    • PostgreSQL
    • Entity Framework Core
    • Stripe API
    • Google APIs
    • Telegram Bots

  5. Hosting

    Where it all runs in production.

    • Linux
    • Nginx
    • Docker
    • Git & GitLab

Around all of it: debugging, problem solving and mentoring.
